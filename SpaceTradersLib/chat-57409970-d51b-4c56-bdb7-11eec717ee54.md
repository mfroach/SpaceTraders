## Recommended Approach: Generic Result Pattern in BaseApiService

Instead of returning raw `ApiResult` with a stream, have your `BaseApiService` methods return a strongly-typed result that handles both success and error cases. This keeps your endpoint services (like `AgentService`) clean and useful.

Here's the structure I'd recommend:

<llm-snippet-file>BaseApiService.cs</llm-snippet-file>
```csharp
using System.Net.Http.Headers;
using System.Text;
using System.Text.Json;
using SpaceTradersLib.Models;
using SpaceTradersLib.Services;

namespace SpaceTradersLib.Http;

public abstract class BaseApiService(HttpClient httpClient) {
    protected readonly HttpClient HttpClient = httpClient;
    protected readonly Deserializer Deserializer = new();

    protected async Task<Result<TSuccess>> GetAsync<TSuccess>(string endpoint) where TSuccess : class {
        try {
            using var response = await HttpClient.GetAsync($"https://api.spacetraders.io/v2/{endpoint}",
                HttpCompletionOption.ResponseHeadersRead);

            var stream = await response.Content.ReadAsStreamAsync();

            if (response.IsSuccessStatusCode) {
                var data = await Deserializer.DeserializeAsync<TSuccess>(stream);
                return Result<TSuccess>.Success(data);
            }

            var error = await Deserializer.DeserializeAsync<Error>(stream);
            return Result<TSuccess>.Failure(error);
        }
        catch (HttpRequestException ex) {
            Console.WriteLine($"HTTP request failed: {ex.Message}");
            return Result<TSuccess>.Failure(new Error { Message = ex.Message });
        }
    }

    protected async Task<HttpResponseMessage?> Post(string endpoint, HttpContent payload) {
        try {
            var response = await HttpClient.PostAsync(new Uri($"https://api.spacetraders.io/v2/{endpoint}"), payload);
            return response;
        }
        catch (HttpRequestException ex) {
            Console.WriteLine($"HTTP POST request failed: {ex.Message}");
            return null;
        }
    }

    internal HttpContent RequestBuilder<TData>(TData content) {
        var json = JsonSerializer.Serialize<TData>(content);
        return new StringContent(json, Encoding.UTF8, "application/json");
    }
}
```

## Explanation of C# Features

Now let's break down the complex parts:

### 1. **Generic Methods with Constraints**

```csharp
protected async Task<Result<TSuccess>> GetAsync<TSuccess>(string endpoint) where TSuccess : class
```

- `<TSuccess>` - This is a **generic type parameter**. It's a placeholder for any type you specify when calling the method.
- `where TSuccess : class` - This is a **generic constraint**. It means `TSuccess` must be a reference type (class), not a value type (int, bool, etc.).

**Example:**
```csharp
// When you call GetAsync<Agent>(), TSuccess becomes Agent
// When you call GetAsync<Ship>(), TSuccess becomes Ship
```

### 2. **Primary Constructors (C# 12+)**

```csharp
public abstract class BaseApiService(HttpClient httpClient)
```

This is shorthand for:
```csharp
public abstract class BaseApiService {
    private readonly HttpClient _httpClient;
    
    public BaseApiService(HttpClient httpClient) {
        _httpClient = httpClient;
    }
}
```

The parameter becomes available throughout the class.

### 3. **Private Constructor Pattern**

```csharp
private Result(bool isSuccess, T? data, Error? error, string? errorMessage = null) {
    // ...
}

public static Result<T> Success(T data) => new(true, data, null);
public static Result<T> Failure(Error error) => new(false, null, error);
```

- The constructor is **private** - no one outside can call `new Result<T>(...)`
- **Static factory methods** (`Success`, `Failure`) control how instances are created
- This ensures `Result<T>` objects are always created correctly (success has data, failure has error)

### 4. **Nullable Reference Types**

```csharp
public T? Data { get; }
public Error? Error { get; }
```

The `?` means the property can be `null`. This is part of C#'s nullable reference type system:
- `T?` - nullable
- `T` - should never be null (compiler warns if it might be)

### 5. **Expression-Bodied Members**

```csharp
public static Result<T> Success(T data) => new(true, data, null);
```

This is shorthand for:
```csharp
public static Result<T> Success(T data) {
    return new Result<T>(true, data, null);
}
```

The `=>` creates a method whose body is a single expression.

### 6. **Target-Typed `new` (C# 9+)**

```csharp
return new(true, data, null);
```

Instead of writing `new Result<T>(true, data, null)`, the compiler infers the type from context (the return type).

## How It All Works Together

When you write:
```csharp
var result = await GetAsync<Agent>("/my/agent");
```

1. The compiler replaces `TSuccess` with `Agent` throughout the method
2. It deserializes the JSON into an `Agent` object
3. It returns a `Result<Agent>` containing either the agent data or an error
4. The caller can check `result.IsSuccess` to see which it is
